# StarScout 要件定義ドラフト

> 本書は現時点での検討内容をまとめたドラフトであり、確定仕様ではない。
> Codex / Claude Code 等を利用した要件定義・設計フェーズで更新することを前提とする。

## 1. プロジェクト概要

### 1.1 プロジェクト名

StarScout

### 1.2 目的

Webサービスや内部サービスを簡単に登録して定期監視し、異常発生時に運用者が迅速に気づけるようにする。

### 1.3 MVPの基本方針

最初から多機能な監視製品を目指さない。

まずは以下を確実に実現する。

- URLを登録できる
- 定期的にHTTP/HTTPSアクセスできる
- サービスの正常・異常を判定できる
- 異常発生時にWindowsへ通知できる
- Windowsタスクトレイで現在状態を確認できる
- Webダッシュボードで詳細状態を確認できる
- 障害開始時刻と復旧を記録できる

## 2. 機能要件

### FR-001 監視対象登録

ユーザーは監視対象となるURLを登録できる。

例:

- `https://example.com`
- `http://example.local:8080`
- `https://api.example.local:8443/health`

登録対象には少なくとも以下の情報を持たせる。

- 表示名
- URL
- ポート番号(任意項目。**【決定】** URLとは別フィールドとして持つ。将来のTCP/Ping監視(Phase3)を見越した項目であり、HTTP/HTTPS監視ではURLに含まれるポート表記を優先し、本項目は補助的に扱う)
- 初期ページタイトル / ページ名(**【決定】** 登録時に自動取得して保持するのみ。MVPの状態判定ロジックには使用しない。将来的な「ページタイトル変更検知」機能(MVP対象外)のための布石)
- 有効 / 無効

### FR-002 複数URL監視

複数の監視対象を登録できる。

監視対象ごとに独立して状態を管理する。

### FR-003 定期監視

設定された間隔で監視対象へHTTP/HTTPSリクエストを実行する。

監視間隔は将来的に設定変更可能とする。

### FR-004 HTTPステータス確認

HTTPレスポンスのステータスコードを取得する。

少なくとも以下を識別可能にする。

- 2xx
- 3xx
- 4xx
- 5xx
- タイムアウト
- 接続エラー
- DNSエラー
- その他通信エラー

**【決定】** 正常とみなすステータスコードは既定で2xxのみとする。監視対象ごとに正常ステータスの上書き設定を可能とする(FR-014)。

3xx/4xx/5xx/タイムアウト/接続エラー/DNSエラー/その他通信エラーは、既定では全て異常(DOWN判定の対象)として扱う。

**【決定】** DOWN判定は「2回連続失敗」を基準とする(1回の一時的なエラーでは即DOWNとしない)。

### FR-005 状態管理

監視対象ごとに現在状態を保持する。

**【決定】** MVPでは以下5状態すべてを採用する。

- NORMAL: 正常
- WARNING: 応答はあるが遅延閾値超過(監視対象ごとに閾値設定可能、既定値あり)
- DOWN: 異常(2回連続失敗で遷移。判定基準はFR-004参照)
- RECOVERED: 異常から正常への復帰直後
- UNKNOWN: 起動直後・初回チェック未実施のみ(登録後、一度もチェックが完了していない状態)

### FR-006 障害開始時刻

監視対象が正常状態から異常状態へ遷移した時刻を記録する。

「いつから落ちているのか」を確認できることを重要要件とする。

### FR-007 復旧検知

異常状態の監視対象が正常状態へ戻ったことを検知する。

復旧時刻を記録する。

### FR-008 障害継続時間

障害開始時刻と復旧時刻から障害継続時間を算出できるようにする。

### FR-009 Windows Toast通知

障害を初めて検知したタイミングでWindows Toast Notificationを表示する。

同一障害について、監視周期ごとに繰り返し通知しない。

### FR-010 復旧通知

障害状態から正常状態へ戻った際に、復旧通知を表示する。

通知内容には以下を含める候補とする。

- サービス名
- URL
- 復旧時HTTPステータス
- 障害継続時間

### FR-010a WARNING通知

**【決定】** WARNING(応答遅延)への遷移時にWindows Toast通知を出すかどうかは、監視対象ごとに設定可能とする(既定値は設計時に決定)。DOWN/RECOVERED通知(FR-009/FR-010)とは独立して制御する。

### FR-011 Windowsタスクトレイ常駐

Windowsクライアントはタスクトレイに常駐する。

タスクトレイアイコンは監視全体の状態を視覚的に表現する。

候補:

- 緑: 正常
- 黄: 警告
- 赤: 異常

### FR-012 タスクトレイTooltip

タスクトレイアイコンへマウスカーソルを合わせた際、現在の異常状況を確認できる。

例:

```text
StarScout
🔴 2 sites DOWN
社内ポータル  HTTP 500
Web API       Timeout
```

### FR-013 ダッシュボード

Webブラウザから現在の監視状態を確認できるダッシュボードを提供する。

候補表示:

- 正常件数
- 警告件数
- 異常件数
- 現在の障害一覧
- HTTPステータス
- 応答時間
- 障害開始時刻
- 障害継続時間
- 復旧履歴

### FR-014 Web設定画面

URL登録や監視設定をWeb UIから変更できる。

候補設定:

- URL
- 表示名
- 監視間隔
- タイムアウト
- 正常ステータス
- WARNING遅延閾値(ms)
- WARNING通知の有効 / 無効
- 有効 / 無効

### FR-015 設定変更の即時反映

設定変更後、監視処理へ適切に反映される。

**【決定】** 設定の変更はWeb UIからのみ行う。変更内容はDBへ直接書き込み、監視エンジンへ即時反映する。設定ファイルによるHot Reloadは採用しない(設定の真のデータはDBのみとし、二重管理を避ける)。

## 3. 非機能要件ドラフト

### NFR-001 軽量性

一般的なWindows PCまたは小規模VMで無理なく動作すること。

### NFR-002 セットアップ容易性

監視を開始するまでの手順を可能な限り少なくする。

理想:

> インストール → 起動 → URL登録 → 監視開始

### NFR-003 常駐性

Windowsクライアントはバックグラウンドで動作し、通常業務の邪魔にならないこと。

### NFR-004 通知抑制

同一インシデントについて通知を大量発生させない。

状態遷移を基本として通知する。

### NFR-005 可視性

現在の異常状態が数秒以内に理解できるUIを目指す。

### NFR-006 拡張性

将来的に監視対象や通知方式を追加できる構造とする。

## 4. MVP対象外候補

以下は将来的な拡張候補とし、MVPでは優先度を下げる。

- ページ本文のキーワード監視
- JSONレスポンスの内容チェック
- ページタイトル変更検知
- SSL証明書期限監視
- DNS監視
- TCP/UDP監視
- Ping監視
- ログイン操作を含むシナリオ監視
- 複数拠点からの監視
- 高度な通知連携
- SSO / RBAC
- SLAレポート
- ステータスページ公開
