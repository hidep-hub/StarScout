親: SS-016 [EPIC] Phase2: 利便性向上

## 前提調査結果

- `check_history.response_time_ms` は既に記録済み(monitor/engine.js → httpChecker.jsで計測)。
- `target_state.last_response_time_ms` で最新値も既にダッシュボードに表示済み(応答時間列)。
- 稼働率・平均応答時間などの**集計メソッドは未実装**(historyRepository/incidentsRepositoryは生SELECTのみ)。
- グラフ描画ライブラリは**未導入**(npm依存ゼロ主義: server/package.jsonに依存関係なし、node:sqlite/node:http組込みのみで完結)。
  → Chart.js等をCDN/vendorで追加するとプロジェクトの「軽量・オフライン動作」方針に反するため、**依存追加なしの手書きSVG折れ線グラフ**で実装する方針とした。

## 設計

### バックエンド

1. `historyRepository.js` に `getStats(targetId, sinceIso)` 追加
   - SQL: `COUNT(*), AVG/MAX/MIN(response_time_ms)` を `checked_at >= sinceIso AND response_time_ms IS NOT NULL` で集計
2. `incidentsRepository.js` に `getStats(targetId, sinceIso)` 追加
   - SQL: `COUNT(*), SUM(duration_sec)` を `started_at >= sinceIso AND recovered_at IS NOT NULL` で集計
   - 制限事項: 期間開始前から継続中のインシデントはカウントされない(Phase2простой集計としての割り切り。将来精緻化の余地あり)
3. 新規API `GET /api/targets/:id/stats?period=24h|7d|30d` (targets.js)
   - uptimePercent = (期間秒 - totalDowntimeSec) / 期間秒 * 100 (0〜100にクランプ)
   - 返却: `{periodHours, avgResponseTimeMs, maxResponseTimeMs, minResponseTimeMs, uptimePercent, incidentCount, totalDowntimeSec}`

### フロントエンド (public/index.html, app.js, style.css)

- 監視対象一覧の各行に「詳細」ボタンを追加
- クリックでモーダル/詳細パネルを開き、以下を表示:
  - 期間切替(24h/7d/30d)タブ
  - 統計カード: 平均応答時間・稼働率・インシデント件数・総ダウンタイム
  - 応答時間の推移(手書きSVG折れ線グラフ、`/api/targets/:id/history?limit=200` を時系列昇順に変換して描画)
